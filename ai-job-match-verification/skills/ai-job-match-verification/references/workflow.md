# Agent workflow
## Profile and required intake
Formal search requires target role family/direction, location scope, numeric nonnegative experience years, and highest education. Ask only what is missing, reuse prior answers, and list optional salary/industry/company/remote/full-time preference/skills/results/resume/availability at the same time. “No industry preference” is an answer; missing education is not. Required basic eligibility data does not imply enough evidence for Matching. A user may provide all four fields and still be in Discovery because projects, responsibilities and outcomes are insufficiently evidenced. Skills remain optional/Unknown. The later three-question adaptive clarification cap does not prevent collecting all missing required intake fields together.

Example: “已知你做过策略增长运营、考虑上海。开始找之前，还需要工作年限和最高学历；你是否希望继续策略/增长运营？如方便，也可一起告诉我期望薪资、行业偏好、擅长的增长环节、SQL/实验分析经验，或发简历。可选项不填也能继续。” Do not re-ask supplied fields.

Record target direction, geography/remote, optional constraints, education, skills and experience. Each skill has state Met/Unknown/Not Met, level unknown/conceptual/learning/personal/work and evidence pointer; missing skill evidence defaults to unknown level. A blank CV is not evidence of inability. Profile matching_ready requires enough referenced experience for the target, not a resume upload alone. Do not persist contact details unless necessary.
## Discovery & verification
Discover through both enabled source kinds. Defaults are examples, not comprehensive coverage or user-selected markets. Add local employer/board sources naturally. Find employer website identity before trusting a supposed official page or external ATS. Record page observation timestamps in UTC, render user-facing time in user timezone. Search excerpts and cached pages remain dated evidence; disclose caching. Never turn relative third-party age into employer publication date.
Every observation: URL, source kind, outcome (open/closed/unknown), checked_at, evidence and method. A page fetch can succeed but outcome remain unknown. Conflicting recent official/third-party reports: show Conflict, preserve both, prefer official for recruiting status. Older observations are history, not current contradictions. Reverification supersedes observations for that URL but retains audit log.
## Semantic normalization
Canonical key is the actual requirement, not a broad bucket: SQL is not equivalent to data analysis. Store category separately (data, programming, AI product, etc.). Aliases require semantic equivalence. Alternatives should be one composite key with acceptable routes and checked as a whole. Never transform “Python or Java” into two mandatory failures. Agent writes JD assessments referencing evidence; helper validates shape and preserves reasoning.
## Adaptive clarification
Use relevant jobs only (exclude Not Relevant/closed/rejected/hard exclusions), count each requirement once per job. Review mandatory prevalence and expected change to ranking or routing. Ask common unknown mandatory requirements if answers meaningfully change results; occasional contextual LLM mention remains Unknown. Large result sets: derive actual clusters (e.g. Python/Java responsibilities or platform/application direction), not generic questionnaires. Distinguish capability from preference. Use Refine only for user-confirmed preferences, or suggest refinement pending an answer. Do not repeat skipped/asked questions unless materially new facts justify reopening with explanation. Only an explicit request for broad/unrestricted exploration sets broad_discovery=true; missing project evidence and Discovery mode do not imply that preference. User wants broad discovery → Proceed even at 300 jobs. Stable unknowns must not reduce ranking as if failures.
## Matching & output
Each assessment lists requirement, JD evidence, candidate evidence or Unknown, level sufficiency and explanation. Mandatory known failures exclude main recommendations only when properly grounded; education requires official evidence. Qualitative fit and relevance have reasons. Never use synthetic percentages. Latest sort uses sourced ISO dates only; unknown dates last. Top10 is a view, full records stay in state/Excel. Surface Unverified/Unknown/Conflict on each row, not only in a footnote.
## Conflict and persistence
Use one writer per state file. Helper lock refuses concurrent writes and atomic replace avoids partial states. Existing local application status wins over conflicting imports; collect explicit pending conflicts. IDs from foreign workspaces are not identity: import resolves by matching source URL, and never creates jobs from a tracker. Restore prior status only via explicit status instruction. Back up private state before deleting it.

## Search completion and fallback
Use source/query logs to establish what was actually searched. Cover official and third-party channels in the selected market, multiple role synonyms and relevant employers. Never stop simply because four or ten candidates are found; continue as long as useful new results emerge, within available access/user scope. If access limits prevent stronger coverage, deliver a clearly incomplete result and the pending work. Do not pad Top10 with irrelevant, expired or invented jobs.
For unreadable official pages attempt an actually available rendered browser or observed ATS alternative, recording outcomes. No browser capability means fallback not available, not fallback performed. Indexed official snippets remain unverified current status. Third-party AI salary/scores/insights are not employer JD facts; do not convert them into requirements or compensation.
Before completion, provide a chat table plus the actual four-sheet Excel, all source states, coverage counts and reason for stopping. An unavailable workbook runtime is an explicit incomplete deliverable, not a successful export. Chinese-facing reports use Chinese labels while stable raw tracker fields remain available for round-trip import.

## Behavioral defects corrected in 0.1.2
Do not suppress adaptive clarification merely because the evaluation mode is Discovery. A per-JD Met/Not Met assessment is already known evidence and should not be asked again; a broad profile skill at a lower level does not automatically satisfy a stronger JD requirement. Review all material qualifications, not just one matching term. Record jd_completeness full/partial/unavailable; only actual read qualifications can be full. Incomplete JD cannot support Strong overall fit. Keep direction relevance independent of personal assessment.
For publicly advertised hiring, an official current specific-role notice and official submission contact/form is sufficient evidence of an open advertisement. Do not submit forms, send emails, or test deliverability. Website restrictions and unobserved destination paths remain Unknown, rather than demanding evidence only achievable by contacting recruiters.
