# 来源、公司优先级与官网反查

用户确认的公司优先级影响搜索覆盖，不代表个人匹配更高，也不覆盖地点、学历等条件。三组内部无默认先后顺序。允许其他公司时必须扩搜，不能把优先公司当白名单。公开包不自动继承个人偏好：用户采用本项目方案时，将 `examples/china-priority-policy.json` 通过 `search-policy` 存入其本地状态；其他用户按自己的偏好配置。不要把历史个人简历、排除公司或城市带入新用户／测试档案。

本项目确认的优先组是阿里系、字节／飞书、Kimi／月之暗面，其他公司也可以。先覆盖这三组的相关职位，再扩展其他相关公司。使用来源注册表中的实际招聘入口；业务独立的阿里系公司须重新发现相应官网入口，不能假设所有职位都在同一站。来源可用自然语言增删，由 Agent 转为 `source` 本地覆盖；禁用的来源不能在下一轮被默认配置重新启用。默认入口只是国内搜索起点，不是完整公司库，也不代表页面可访问或存在目标岗位。其他市场需调整来源。

## 第三方线索与官网反查

1. 从第三方提取真实公司、团队、城市、岗位名称、岗位 ID、日期和 JD；未提供的字段留空。
2. 定位该公司／业务对应的官方招聘入口，只使用观察到的链接。
3. 依次尝试岗位 ID、完整名称、名称关键词、职责与要求内容。第三方 ID 不一定是官网 ID；不得拼接岗位 URL。
4. 对照城市、团队、职责和要求确认职位身份。明确同一职位才合并；仅疑似对应时保留独立记录或交叉说明，不自动合并。官网首页不是岗位核验结果。
5. 日志记录实际尝试、结果和限制。官网找到同一职位时，提供官网岗位链接并保留第三方来源。找不到时写“未找到官网对应职位”，保留真实第三方岗位链接及推荐资格；浏览受阻则写“官网访问受阻，未完成核验”，不能声称没搜到。

核验分清：官网确认同一职位、疑似对应待人工确认、第三方线索且官网未核验、明确已关闭。404、无搜索结果、网页不可读均不能单独证明关闭。官方与第三方冲突要显式展示。来源有证据的第三方线索可进入推荐，仍须展示“招聘状态待核实”，解释这表示尚未确认当前在招，而不是已停止招聘。仅有索引片段时说明 JD／状态证据有限，不伪造完整要求；无任何来源观察的记录默认不进入推荐。

## 输出

默认最多展示10条，不能因此只搜索10条。完整 Excel 保留全部岗位和来源日志。主表通常只保留一个直接岗位链接；同一岗位另有已确认官网链接时，应在聊天表／补充列给出该官网链接，第三方原链接可查核验日志。疑似官网岗位应把两个链接并列解释，不能替换为已确认官网职位。用具体未知条件和匹配理由，不显示“匹配0个／2个”等内部计数；评估模式统一说明一次。

## 本地配置命令

从仓库根目录执行，状态路径由用户运行环境选择：

```sh
python3 skills/ai-job-match-verification/scripts/jobmatch.py --state jobmatch-private/state.json search-policy examples/china-priority-policy.json
python3 skills/ai-job-match-verification/scripts/jobmatch.py --state jobmatch-private/state.json search-plan
```

`search-plan` 是待执行计划，不代表已检索；只有实际执行后才写 `search-log`。优先组不能自动增加匹配评分。排序仍由岗位相关性／证据匹配／实际发布日期决定。

安装后的 Skill 也包含 `references/china-priority-policy.json`，无需保留仓库 examples 文件夹。采用上述已确认方案时，把此文件的绝对路径传给 `search-policy` 即可。新用户未表达公司偏好时，不自动启用该优先组。
