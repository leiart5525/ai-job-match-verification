# AI Job Match & Verification — MVP PRD
版本 0.1.2；2026-10-15；公开发布准备包，未发布。

## 用户价值与边界
帮助用户发现真实岗位、核验来源并管理投递。Agent 完成搜索、JD语义理解、档案确认与证据解释；Python helper 完成持久化、去重、状态与导出。无需服务端或模型 API 密钥。
不自动投递，不发送消息，不自动修改简历，不提供虚构匹配百分比。

## 已确认决策
- PDF/DOCX/TXT 简历抽取或对话式档案；保留原始来源与经验层级。扫描 PDF 无可提取文本时需 OCR/用户确认，不能猜测。
- Discovery：缺少可支持匹配的经历证据，仅按 JD 职责分 Directly Relevant / Adjacent / Exploratory / Not Relevant，解释理由。AI 平台产品同样可直接相关。
- Matching：有可引用的角色/项目、职责、成果和技能证据；逐项 Met / Unknown / Not Met。Unknown 永不排除。匹配等级 Strong / Partial / Needs clarification，解释依据，非成功概率。
- 官网与第三方双渠道；来源默认配置与本地覆盖/禁用，支持自然语言操作。搜索覆盖、失败、限制必须披露，不能声称全网完整。
- 去重优先已核对的公司+requisition ID，其次已确认相同职位链接；跨平台相同名称仅候选重复，Agent 确认后关联 merge_into。保留多来源及核验日志。
- 官网明确必备学历与用户明确不满足才是学历硬排除。等价经验/学历替代必须保留。第三方与官网冲突保留双方，官网优先；404/403/超时均不是关停证明。
- 招聘状态与投递状态分离；历史岗位重新核验保留编号/用户状态。已拒/已拒绝推荐/撤回不再次推荐，除非用户主动恢复。
- 自适应澄清：按相关岗位分母、要求强制性、影响岗位数、未知证据与提问负担选择 Ask / Keep Unknown / Refine / Proceed。300岗位应提炼有区分力的问题；偶发要求保持未知。用户广泛探索时尊重选择，最多一轮3个关键问题，跳过不重复询问。
- 默认 Top10，允许匹配度/相关性/最新排序；发布日期未知排后，first_seen 不冒充 published_at。
- Excel 包含 All Jobs、Recommended、Application Tracker、Verification Log。J001起单调编号，原子持久化；导入仅合并受限用户状态，冲突显式记录，永不静默覆盖。
- 针对 JD 提供简历优化建议，引用真实经历，不发明技能/指标。
- 定时任务使用宿主调度工具，仅能力探测并实际验证后称可用。本包不安装后台服务；无人授权时不创建定时任务。

## 验收
参见 tests/test_engine.py 与 TEST-REPORT.md。真实来源测试保留简短事实摘要和观察时间；模拟数据明确标注，不混入真实求职状态。发布包不得包含个人简历、私人档案或投递记录。

## 0.1.1 用户试用反馈修正
必要条件：岗位方向、地点范围、工作年限、最高学历。缺失时先集中确认，不启动正式搜索；可选条件在同一轮列出并鼓励提供，不阻断。即使必要信息齐全，缺少经历证据仍为 Discovery。Unknown 技能不变。
Top10为展示上限，不是搜索上限。搜索必须覆盖市场适配的双渠道、多同义词和雇主来源，记录实际覆盖/候选/去重/核验/排除；不足10解释停止原因，不能称全市场仅此数量。官网读取失败采用可用的不同读取方式并记录结果；未完成仍为 Unknown。完成交付必须聊天表格和实际四表 Excel；无导出运行时只能称不完整交付。

## 0.1.2 行为验收
以docs/behavior-tests/REPORT.md记录的真实试用、失败及修复复测为准。31项脚本回归是辅助；网络不完整明确保留，不用测试数量冒充市场覆盖。

## 当前确认的来源策略（0.1.4）
本项目优先覆盖阿里系、字节／飞书、Kimi／月之暗面，允许扩展其他公司；以本地偏好配置，不能作为全体用户的强制白名单。优先级不增加匹配分。第三方线索发现后逐层反查官方入口、ID、名称、关键词和JD内容。官网未找到或访问受阻分别记录，第三方真实岗位仍可推荐并明确待核实。疑似对应不自动合并；官网明确关闭、个人已拒／不考虑等原排除条件继续生效。此条替代旧版仅官网确认才能推荐的要求。
